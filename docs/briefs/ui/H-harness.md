# Silo H: Client test harness

**Wave 0**, from day one. O, G, R, S and L write their client tests on it, so land the run and the driver (deliverables 1 and 2) in the first merge, even before C's fake MCP exists.

**Specs:** `16` (*Testing*, *Mod, client half*), `10` (test tiers), `world/test-setup.md` (the manual checklist this harness takes over).

## Goal

A real Minecraft client, booted headless with software rendering, that runs scripted steps against the mod and the fake MCP, writes a report and exits, here and on the CI runner.

## Deliverables, in merge order

1. **`clientTest` run** in `mod/neoforge/build.gradle`: `client()`, the existing `gametest` source set, `--quickPlaySingleplayer <test world>`, a report path, its own game directory (`run/clienttest`). The test world is generated by the run (flat, creative, cheats on) when missing, never committed. A wrapper script `mod/clienttest.sh` runs it under `xvfb-run -a` with `LIBGL_ALWAYS_SOFTWARE=1` and exits non-zero on any failed step or a timeout. The test code never ships in the jar (check the built jar).
2. **Driver** (`mod/neoforge/src/gametest/.../client/`), copying NeoForge's `SelfTestClient` pattern: a client tick listener that waits for the title or loading screen to go, runs a suite's steps in order, writes the report, calls `Minecraft.stop()`. `step(name, action)`, `waitUntil(name, condition, timeoutTicks)` (fails the step with the condition's name), helpers for `KeyMapping.click`/`set`, `ClientHooks.onMouseScroll`, opening and clicking screen widgets, and `Screenshot.takeScreenshot` compared to a reference with a tolerance (reference images record the Mesa version, and a mismatch in version skips the pixel check with a warning rather than failing). One boot per suite; suites selected by a system property.
3. **Fake MCP wiring:** the suite starts C's fake MCP CLI against the dev run's pairing file, with a per-suite script, and stops it at the end. Until C lands, a placeholder that only connects is enough.
4. **First test:** air mode left click into the air sets corner 1 (the case in `16`, *Input*). Then the rest of `world/test-setup.md`'s player-only checks that a client can drive: air mode's scroll distance and outline, `/autosketch done` and its action-bar notice. The vanilla-client join stays a GameTest or e2e check; note in the brief's merge request which checklist items the harness now covers.
5. **`xdotool` test:** one test that sends a real OS key through `xdotool` to the Xvfb display. Skipped with a clear message when `xdotool` isn't installed (it is on the dev machine; install it in the CI job too).
6. **CI:** a job in `.github/workflows/mod.yml` on `ubuntu-latest` that installs Xvfb and Mesa and runs `clienttest.sh` on the dev profile, uploading the report and screenshots on failure. A Craftoria-sized run (532 mods, `~/servers/craftoria`'s mod list on the client) is a separate manual script, documented, not in CI.
7. **Timings:** boot time to the first step with software rendering, on the dev machine and on the CI runner, recorded in `16`'s *Testing*.

## Files you own

- `mod/neoforge/build.gradle` (the `clientTest` run only), new `mod/clienttest.sh`, new `mod/neoforge/src/gametest/.../client/**` (driver and the tests in deliverables 4–5), `.github/workflows/mod.yml` (the client job), the timing lines in `16`.

## Notes

- Every entry point is public (`16`, *Testing*): no mixin, reflection or access transformer. If one turns out not to be, stop and raise it.
- Each feature silo puts its own tests in its own package under the client test folder (`client/overlay/`, `client/ghost/`, `client/replay/`, `client/screen/`); H owns only the driver and its own tests.
- L's offline lock lands in parallel: the air mode test needs a connected MCP once L merges, so start the fake MCP in the suite from the beginning.

## Done when

- `mod/clienttest.sh` passes from a clean checkout on the dev machine and in CI, and a deliberately broken step fails it with the step's name in the output.
- The first test passes against the real air mode code.
- Boot timings are recorded.
